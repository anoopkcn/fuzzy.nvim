1. INTRODUCTION                                          *fuzzy-introduction*

Fuzzy provides a simple, fast interface for searching files, grepping code,
and managing buffers using Neovim's built-in quickfix list. Unlike heavier
plugins, fuzzy leverages external tools (ripgrep and fd) and native Vim
functionality for maximum performance.

Features:
  • Help tag browser with language-priority-aware tag discovery
  • Fast grep search using ripgrep with smart case matching
  • Live grep picker with per-session result cache and match highlighting
  • File finding using fd with gitignore support
  • Buffer switching with fuzzy filtering
  • Command palette for built-in, user, plugin commands, and Neovim options
  • Keymap browser for global and buffer-local keymaps across every mode
  • Git branch browser/switcher
  • Git worktree browser/switcher
  • LSP document symbol browser (current buffer)
  • LSP workspace symbol browser with live re-query
  • Quickfix history navigation
  • Jump-list browser (:jumps) — pick to jump cross-buffer
  • Marks browser (:marks) — global A-Z + 0-9 and buffer-local marks
  • Registers browser (:reg) — pick to copy contents to the system clipboard
  • Send picker results to quickfix with a single key (<M-q> by default)
  • Single-file direct opening
  • Full control over search arguments

==============================================================================
2. REQUIREMENTS                                          *fuzzy-requirements*

  • Neovim 0.11+

Optional external programs:
  • ripgrep (rg) - for :FuzzyGrep (fallback: grep -R)
  • fd - for :FuzzyFiles (fallback: vim.fs.find)
  • git - for :FuzzyGitBranches and :FuzzyGitWorktrees

Install via your package manager:
    macOS:    brew install ripgrep fd
    Ubuntu:   apt install ripgrep fd-find
    Arch:     pacman -S ripgrep fd

3. COMMANDS                                                  *fuzzy-commands*

All commands follow a consistent convention:

    No [!]  Populate the quickfix list.
    [!]     Open the interactive picker.

Passing arguments to the [!] form pre-fills the picker's search query. In the
live grep pickers, ripgrep options are also preserved and can be edited inside
the picker.

Note: |:FuzzyHelp|, |:FuzzyCommands|, |:FuzzyMap|, |:FuzzyGitBranches|,
|:FuzzyGitWorktrees|, |:FuzzyJumps|, |:FuzzyMarks|, and |:FuzzyReg| always
open the picker and do not have a quickfix-only mode.

|:FuzzyLspSymbols| and |:FuzzyLspProjectSymbols| require an attached LSP
client that supports |textDocument/documentSymbol| or |workspace/symbol|
respectively, and notify (without creating a quickfix list) when none does.

Inside picker types that support quickfix export, press <M-q> (Alt+q,
configurable via |fuzzy-send_to_qf_key|) to send the currently visible
(filtered) results to the quickfix list and close the picker. If you marked
entries with <Tab>, the marked entries are sent instead:
  • FuzzyGrep!               → populates the FuzzyGrep quickfix list
  • FuzzyFiles!              → populates the FuzzyFiles quickfix list
  • FuzzyBuffers!            → populates the FuzzyBuffers quickfix list
  • FuzzyHelp                → populates the FuzzyHelp quickfix list (entries jump to tag location)
  • FuzzyLspSymbols!         → populates the FuzzyLspSymbols quickfix list
  • FuzzyLspProjectSymbols!  → populates the FuzzyLspProjectSymbols quickfix list
FuzzyCommands stages commands in the command line instead of exporting to
quickfix. FuzzyGitBranches and FuzzyGitWorktrees perform Git switch actions and
do not export to quickfix. FuzzyMap is a browser only and does not export to
quickfix or invoke the selected keymap.

In :FuzzyGrep!, press <M-r> (Alt+r, configurable via
|fuzzy-edit_grep_flags_key|) to edit ripgrep backend flags without leaving the
picker.

Use standard quickfix navigation: >
    :cnext      " Next item
    :cprev      " Previous item
    :copen      " Open quickfix window
    :cclose     " Close quickfix window
<

3.1 FuzzyGrep                                                    *:FuzzyGrep*

Search for patterns in files using ripgrep.

Syntax: >
    :FuzzyGrep[!] [pattern] [rg options]
<
The command uses ripgrep with these default flags:
  --vimgrep       Output in vim-compatible format
  --smart-case    Case insensitive unless pattern contains uppercase

Without [!]: Streams ripgrep results directly to the quickfix list.
             Requires a pattern; shows a notification if none is given.
With [!]:    Opens a live grep picker that streams matches as you type.
             Optionally pre-fills the picker with [pattern] and initial
             ripgrep options.

The live grep picker includes a per-session result cache:
  • Prefix narrowing: typing a longer query (e.g. "foobar" after "foo")
    instantly filters the cached "foo" results while grep runs in the
    background for completeness.
  • Exact hit: typing the same query again skips grep entirely.
  • Matched text is highlighted within each result line.

Deduplication is controlled by |fuzzy-grep_dedupe|.

Examples: >
    :FuzzyGrep TODO                    " stream to quickfix
    :FuzzyGrep function.*init
    :FuzzyGrep -t lua require
    :FuzzyGrep -i error -g '*.yml'
    :FuzzyGrep! TODO                   " open picker pre-filled with 'TODO'
    :FuzzyGrep! TODO -t lua            " open picker with initial rg flags
    :FuzzyGrep!                        " open live grep picker (empty)
<
Common ripgrep options:
    -t TYPE     Search only files of TYPE (lua, py, js, etc.)
    -g GLOB     Include/exclude files matching glob pattern
    -i          Case insensitive search
    -w          Match whole words only
    -F          Treat pattern as literal string (not regex)
    --hidden    Search hidden files
    --no-ignore Don't respect .gitignore

See `rg --help` for full options.

Inside the picker, press <M-r> (|fuzzy-edit_grep_flags_key|) to edit ripgrep
backend flags without closing the picker. Result caching is scoped by both the
query and the active backend flags.

3.2 FuzzyFiles                                                  *:FuzzyFiles*

Find files using fd.

Syntax: >
    :FuzzyFiles[!] [fd arguments]
<
Without [!]: Runs fd and streams results to the quickfix list.
With [!]:    Opens the file picker (from cache). Optionally pre-fills
             the picker with a query.

Default fd behavior:
  • Searches from current working directory
  • Respects .gitignore
  • Includes hidden files
  • Excludes .git directory
  • Limits results to 10000 files (configurable)
  • Results stream incrementally (no UI hang on large directories)

Examples: >
    :FuzzyFiles                        " stream all files to quickfix
    :FuzzyFiles .lua$                  " stream filtered results to quickfix
    :FuzzyFiles -e go --max-depth 2
    :FuzzyFiles --no-ignore config
    :FuzzyFiles!                       " open file picker
    :FuzzyFiles! init                  " open picker pre-filled with 'init'
<
Common fd options:
    -e EXT          Filter by extension
    -t TYPE         Filter by type: f=file, d=directory
    -E PATTERN      Exclude pattern
    --max-depth N   Limit search depth

See `fd --help` for full options.

Unlike the live grep pickers, :FuzzyFiles! does not edit backend fd flags from
inside the picker; it filters the warmed file cache by query only.

------------------------------------------------------------------------------
3.3 FuzzyBuffers                                              *:FuzzyBuffers*

List and filter open buffers.

Syntax: >
    :FuzzyBuffers[!] [pattern]
<
Without [!]: Shows all open buffers (optionally filtered by [pattern])
             in the quickfix list.
With [!]:    Opens the interactive buffer picker. Optionally pre-fills
             the picker with [pattern].

Only includes listed buffers (excludes quickfix, help, terminal, etc.)

Examples: >
    :FuzzyBuffers               " all buffers in quickfix
    :FuzzyBuffers lua           " quickfix filtered by 'lua'
    :FuzzyBuffers!              " open buffer picker
    :FuzzyBuffers! init         " open picker pre-filled with 'init'
<
Inside :FuzzyBuffers!, <C-x> closes the buffer under the cursor, or every
<Tab>-marked buffer at once. Buffers with unsaved changes are skipped and
reported in a notification; underlying windows showing a closed buffer are
swapped onto another listed buffer first to avoid surfacing [No Name]. The
picker refreshes in place and closes when the last listed buffer is gone.
The key is configurable (see |fuzzy-close_buffer_key|).

Pressing <CR> with two or more <Tab>-marked entries opens the first marked
buffer in the current window and the remaining ones as splits. The split
direction is controlled by |fuzzy-buffer_split_direction| ("vertical" or
"horizontal", default "vertical"); splits respect 'splitright' / 'splitbelow'.

3.4 FuzzyCommands                                          *:FuzzyCommands*

Browse built-in, user, and plugin commands available in the current Neovim
session, plus Neovim options such as 'relativenumber'.

Syntax: >
    :FuzzyCommands [query]
<
Always opens the interactive picker. There is no quickfix-only mode and no
[!].

Command discovery combines |getcompletion()| for available command names with
|nvim_get_commands()| metadata for user/plugin command descriptions. Option
discovery uses |nvim_get_all_options_info()| and current option values.
Readable alphabetic command names are shown by default; punctuation commands
such as !, #, =, and ~ are hidden.

Entries are rendered as aligned CMD/OPT rows. Option aliases use their own
column, and long descriptions or option values are trimmed to the picker width
without changing the staged command.

Press <CR> to stage the selected command or option edit in the command line.
Examples include :FuzzyFiles<Space> and :set relativenumber<Space>.

Examples: >
    :FuzzyCommands              " open command picker
    :FuzzyCommands edit         " picker pre-filled with 'edit'
    :FuzzyCommands relativenumber " picker pre-filled with 'relativenumber'
    :FuzzyCommands Fuzzy             " pre-filled with 'Fuzzy'
<

3.7 Picker keymaps                                      *fuzzy-picker-keys*

Interactive pickers share these insert-mode keymaps:

    <CR>            Accept selection and open / jump to result. If entries
                    are marked with <Tab>, file-backed pickers load the
                    marked files as buffers and show one of them.
    <C-n> / <Down>  Move to next result
    <C-p> / <Up>    Move to previous result
    <Tab>           Mark current result
    <S-Tab>         Unmark current result
    <Esc> / <C-c>   Close picker without selecting
    <M-q>           Send visible (filtered) results to quickfix and close,
                    or send marked results if any are selected
                    where supported
                    (key is configurable, see |fuzzy-send_to_qf_key|)
    <M-r>           Edit ripgrep backend flags in :FuzzyGrep!
                    (key is configurable, see
                    |fuzzy-edit_grep_flags_key|)
    <C-x>           In :FuzzyBuffers! close the buffer under the cursor,
                    or every <Tab>-marked buffer when entries are marked
                    (key is configurable, see |fuzzy-close_buffer_key|)
    <M-p>           Toggle the preview pane in :FuzzyFiles, :FuzzyBuffers,
                    :FuzzyGrep!, :FuzzyHelp, :FuzzyLspSymbols!,
                    :FuzzyLspProjectSymbols!
                    (key is configurable, see |fuzzy-preview_toggle_key|)
    <M-w>           Move focus into the preview pane. Use vim motions to
                    navigate; v/V to select; y to yank; <Esc>/q/<CR> to
                    return to the picker input
                    (key is configurable, see |fuzzy-preview_focus_key|)
    <C-d> / <C-u>   Scroll the preview pane half-page down / up
                    (no-op when preview is hidden; see
                    |fuzzy-preview_scroll_down_key| and
                    |fuzzy-preview_scroll_up_key|)
    Mouse wheel     Scroll the preview pane by 'mousescroll' lines per
                    tick. Requires 'mouse' to include "i" or "a" so the
                    wheel events reach insert mode. No-op when the
                    preview is hidden.

The <M-q> key respects the current filter query: only items visible in the
picker at that moment are sent to quickfix when nothing is marked. This lets
you narrow results with a query and then export that subset to the quickfix
list. In |:FuzzyBuffers!|, marked entries are already loaded, so <CR> does
not re-read them from disk; with two or more marked, <CR> opens the first
marked buffer in the current window and the rest as splits (direction set
by |fuzzy-buffer_split_direction|). |:FuzzyCommands| does not expose <M-q>
because command entries are actions, not file locations.

3.8 FuzzyHelp                                                    *:FuzzyHelp*

Browse and open Neovim/Vim help tags.

Syntax: >
    :FuzzyHelp [query]
<
Always opens the interactive picker. Unlike other fuzzy commands, there is no
quickfix-only mode — the picker is the primary interface.

Tag discovery reads doc/tags and doc/tags-{lang} files across the full
|runtimepath|. Language priority follows |'helplang'|, with "en" appended as
a fallback. Duplicate tags resolve in language-priority then runtimepath
order, matching Vim's own tag resolution.

Each picker entry shows:  tagname  filename.txt

Filtering matches against both the tag name and the filename, so you can
narrow by topic (e.g. "autocmd") or by plugin file (e.g. "lsp.txt").

Press <CR> to open the tag with |:help|.
Press <M-q> (|fuzzy-send_to_qf_key|) to export visible tags to the quickfix
list. Quickfix entries resolve to the exact tag location in the help file.

Examples: >
    :FuzzyHelp                   " open help tag picker
    :FuzzyHelp autocmd           " open picker pre-filled with 'autocmd'
    :FuzzyHelp lsp.txt           " filter to tags from lsp.txt
<

3.9 FuzzyGitBranches                                      *:FuzzyGitBranches*

Browse and switch Git branches.

Syntax: >
    :FuzzyGitBranches [query]
<
Always opens the interactive picker. There is no quickfix-only mode because
branch entries are actions, not file locations.

The picker lists local and remote branches, marks the current branch with *,
and shows upstream information for local branches when available. Filtering
matches branch names, kind, upstream, and SHA.

Press <CR> to switch to the selected branch:
  • current branch: no-op notification
  • local branch:   git switch <branch>
  • remote branch:  git switch --track <remote>

Examples: >
    :FuzzyGitBranches              " open branch picker
    :FuzzyGitBranches feat         " picker pre-filled with 'feat'

3.11 FuzzyMap                                                      *:FuzzyMap*

Browse keymaps registered in the current Neovim session.

Syntax: >
    :FuzzyMap [query]
<
Always opens the interactive picker. There is no quickfix-only mode and no
[!]. Pressing <CR> closes the picker without invoking the selected keymap —
this command is currently a browser only.

Entries combine global keymaps from |nvim_get_keymap()| and buffer-local
keymaps from |nvim_buf_get_keymap()| for the buffer that was active when
:FuzzyMap was invoked. All Neovim mode short-names are queried: n, i, v, x,
s, o, c, t, l, and !. Hard-coded built-in keys (such as j, dd) are not
returned by these APIs and do not appear in the list.

Each entry renders as three aligned columns:

    mode │ lhs                  │ detail

The mode column is two characters wide: the mode short-name, followed by `*`
when the entry is a buffer-local keymap (a plain space for global maps).
Maps registered with `:map` (no mode prefix, applying to NVO) appear with
mode " " — they are returned by the API under that pseudo-mode.

The detail column prefers the keymap's `desc`; if absent it falls back to
the keymap's `rhs` string, and finally to "<function>" when the keymap is a
Lua callback with no string `rhs`.

Filtering matches the mode, lhs, and detail text simultaneously, so you can
narrow by mode ("i "), by key sequence ("<leader>ff"), or by description
("signature").

Examples: >
    :FuzzyMap                  " open keymap picker
    :FuzzyMap leader           " picker pre-filled with 'leader'
    :FuzzyMap signature        " find keymaps mentioning 'signature'
<

3.12 FuzzyLspSymbols                                        *:FuzzyLspSymbols*

Browse LSP document symbols (functions, classes, variables, etc.) for the
current buffer.

Syntax: >
    :FuzzyLspSymbols[!] [pattern]
<
Without [!]: Sends document symbols returned by the LSP server to the
             FuzzyLspSymbols quickfix list and opens it. When [pattern] is
             given, the list is filtered to symbols whose label (the
             "[Kind] name in Container" text) contains [pattern] as a
             literal (case-insensitive) substring.
With [!]:    Opens the interactive picker with a file preview pinned to the
             symbol under the cursor. [pattern] pre-fills the picker query.
             Press <M-q> to export the visible (filtered) symbols to the
             FuzzyLspSymbols quickfix list.

The command queries every attached LSP client that supports
|textDocument/documentSymbol| and merges their responses (dedup by location +
label, stable order by file → line → column). If no attached client supports
the method, the command notifies and exits without creating a quickfix list.

Each entry shows: >
    [Kind] container.name
<
The container prefix only appears when the symbol is nested (method on a
class, field on a struct, etc.). Deprecated symbols are tagged at the end.
Filtering matches the kind, container, and name together — type "func" to
narrow to functions, "MyClass" to narrow to one class, or "MyClass.do" to
narrow to a specific method.

Press <CR> to jump to the symbol's definition. Marked entries (<Tab>) load
all marked files as buffers and jump to one of them.

Examples: >
    :FuzzyLspSymbols                " all symbols → quickfix
    :FuzzyLspSymbols!               " open picker with preview
    :FuzzyLspSymbols! init          " picker pre-filled with 'init'
<

3.13 FuzzyLspProjectSymbols                          *:FuzzyLspProjectSymbols*

Browse LSP workspace symbols across the entire project.

Syntax: >
    :FuzzyLspProjectSymbols[!] [query]
<
Without [!]: Runs one |workspace/symbol| request with [query] and sends the
             matching symbols to the FuzzyLspProjectSymbols quickfix list.
             Most LSP servers return nothing for an empty [query]; pass at
             least one character for useful results.
With [!]:    Opens an interactive picker that re-queries the LSP server live
             as you type, debounced at 150ms. Each keystroke after the
             debounce window fires a fresh workspace/symbol request; the
             previous in-flight request is cancelled, so only the latest
             query's results land in the picker. An empty input shows
             nothing and skips the request. Press <M-q> to export the
             current visible (filtered) snapshot to the
             FuzzyLspProjectSymbols quickfix list.

Each entry shows: >
    [Kind] container.name │ relative/path/to/file:lnum
<
Filtering in the bang picker is server-side: the LSP server decides which
symbols match your query, so behavior (substring vs. fuzzy, case sensitivity)
matches whatever your language server does. The relative path is also part
of the filter input, so typing a path fragment narrows by file.

The command queries every attached LSP client that supports
|workspace/symbol|, merging and deduping responses identically to
|:FuzzyLspSymbols|.

Press <CR> to jump to the symbol's location in the project. Marked entries
(<Tab>) load all marked files as buffers and jump to one of them.

Examples: >
    :FuzzyLspProjectSymbols MyClass      " one-shot workspace query → quickfix
    :FuzzyLspProjectSymbols!             " open picker, type to live-search
    :FuzzyLspProjectSymbols! parse_      " open picker pre-filled with 'parse_'
<

3.14 FuzzyJumps                                                  *:FuzzyJumps*

Browse the jump list (|:jumps|).

Syntax: >
    :FuzzyJumps [query]
<
Always opens the interactive picker. There is no quickfix-only mode and no
[!]. Pressing <CR> jumps to the selected location across buffers.

Entries are sourced from |getjumplist()|. The picker shows the list newest
first (reverse of |:jumps|), so the most recent jump is at the top. Each row
renders as four aligned columns: >

    mark │ lnum:col │ rel/path │ line text
<
The mark column is a single character: ">" for the current jump-list position
(the line |:jumps| highlights with ">"), or a space otherwise. Jumps whose
buffer is no longer valid are skipped during collection.

Filtering matches the relative path and the line text together, so you can
narrow by file ("init.lua") or by content ("TODO").

Press <CR> to switch to the target buffer (reusing an existing window if one
is displaying it) and move the cursor to the recorded lnum:col. The preview
pane, when enabled, centers on the jump location.

Examples: >
    :FuzzyJumps                  " open jump-list picker
    :FuzzyJumps init.lua         " picker pre-filtered to 'init.lua'
<
------------------------------------------------------------------------------
3.15 FuzzyMarks                                                  *:FuzzyMarks*

Browse global and buffer-local marks.

Syntax: >
    :FuzzyMarks [query]
<
Always opens the interactive picker. There is no quickfix-only mode and no
[!]. Pressing <CR> jumps to the selected mark.

Entries combine global marks from |getmarklist()| (uppercase A-Z and 0-9)
with buffer-local marks from |getmarklist()| called on the buffer that was
current when |:FuzzyMarks| was invoked (lowercase a-z plus special marks
`'`, `` ` ``, `.`, `^`, `[`, `]`, `<`, `>`). Marks with `lnum == 0` (unset)
are filtered out.

Each entry renders as five aligned columns: >

    name │ G/L │ lnum:col │ rel/path │ line text
<
The "G/L" column distinguishes global from buffer-local marks. Filtering
matches name, scope, path, and line text simultaneously.

Press <CR> to jump. Alphanumeric marks use vim's native backtick-jump
(`` `<name> ``), which preserves cross-file semantics for global marks
(e.g. mark A in another file is opened automatically). Special marks fall
back to a manual buffer switch + cursor placement.

The preview pane, when enabled, centers on the mark location.

Examples: >
    :FuzzyMarks                  " open marks picker
    :FuzzyMarks A                " picker pre-filtered to global mark A
    :FuzzyMarks global           " picker pre-filtered to global marks
<
------------------------------------------------------------------------------
3.16 FuzzyReg                                                      *:FuzzyReg*

Browse non-empty registers.

Syntax: >
    :FuzzyReg [query]
<
Always opens the interactive picker. There is no quickfix-only mode and no
[!].

Entries are sourced from |getreginfo()| for the standard register set: the
unnamed register `"`, the selection registers `*` and `+`, the small-delete
register `-`, the read-only specials `/`, `:`, `.`, `%`, `#`, the numbered
registers `0`-`9`, and the named registers `a`-`z`. Empty registers are
hidden from the picker.

Each entry renders as three aligned columns: >

    name │ type │ preview
<
The "type" column shows the regtype as `c` (charwise), `l` (linewise), or
`b` (blockwise). The "preview" column shows the first line of the register
contents; multi-line registers are suffixed with `↵` so you can tell at a
glance.

Press <CR> to copy the register's contents to the system clipboard (`+`),
preserving the original regtype so a subsequent `p` pastes with the same
charwise/linewise/blockwise semantics. A notification confirms the copy.

This picker has no preview pane in v1.

Examples: >
    :FuzzyReg                    " open registers picker
    :FuzzyReg 0                  " picker pre-filtered to the yank register
<

4. CONFIGURATION                                        *fuzzy-configuration*

Setup the plugin in your init.lua: >
    require('fuzzy').setup({
        open_single_result = false,
        file_match_limit = 10000,
        grep_dedupe = true,
        grep_path_truncate = true,
        send_to_qf_key = "<M-q>",
        edit_grep_flags_key = "<M-r>",
        close_buffer_key = "<C-x>",
        buffer_split_direction = "vertical",
        preview = false,
        preview_toggle_key = "<M-p>",
        preview_focus_key = "<M-w>",
        preview_scroll_down_key = "<C-d>",
        preview_scroll_up_key = "<C-u>",
        preview_grep_context = 10,
        preview_max_lines = 5000,
        window = {
            height = 0.4,
            width  = 0.6,
            row    = 0.0,
            col    = 0.5,

grep_path_truncate~
    Type: boolean
    Default: true

In the live-grep picker (:FuzzyGrep!), when a result line

                                                 *fuzzy-close_buffer_key*
close_buffer_key~
    Type: string|false
    Default: "<C-x>"

Key (in insert mode) used inside :FuzzyBuffers! to close the buffer under

------------------------------------------------------------------------------
                                                         *fuzzy-preview*
preview~
    Type: boolean
    Default: false

When true, the preview pane opens automatically each time a supported picker
opens. Supported pickers: :FuzzyFiles, :FuzzyBuffers, :FuzzyGrep!,
:FuzzyHelp, :FuzzyLspSymbols!, :FuzzyLspProjectSymbols!.

The pane is anchored below the picker. If there isn't enough vertical room
for both, the preview is skipped and a one-shot notification fires.

The preview window is focusable and the buffer is read-only — click into
it (or press the |fuzzy-preview_focus_key|, default <M-w>) to select and
yank text without dismissing the picker. Once focused, use vim motions
(hjkl, gg, G, /, etc.), v/V/<C-v> for visual selection, and y to yank.
From inside the preview press <Esc>, q, or <CR> to return focus to the
picker input.

preview_toggle_key~
    Type: string|false
    Default: "<M-p>"

Insert-mode key inside a supported picker that toggles the preview pane on or
off for the current session.

Set to false to disable the mapping entirely. >
    require('fuzzy').setup({ preview_toggle_key = false })
<
------------------------------------------------------------------------------
                                              *fuzzy-preview_focus_key*
preview_focus_key~
    Type: string|false
    Default: "<M-w>"

Insert-mode key that moves focus from the picker into the preview pane.
Once focused, the preview's read-only buffer accepts standard vim motions
(hjkl, gg, G, /, etc.), visual-mode selection (v, V, <C-v>), and yanking
(y / "+y for the system clipboard). Press <Esc>, q, or <CR> inside the
preview to return focus to the picker input. No-op while the preview is
hidden.

Set to false to disable the mapping entirely. >
    require('fuzzy').setup({ preview_focus_key = false })

window~
    Type: table
    Default: { height=0.4, width=0.6, row=0.0, col=0.5, border="rounded",
               title_pos="center" }

Picker window geometry. height/width are fractions of the editor; row/col
are positions within the free space (0=top/left, 1=bottom/right, 0.5 =

------------------------------------------------------------------------------
                                                      *fuzzy.register_source()*
require('fuzzy.picker').register_source({kind}, {modname})
    Register a custom picker source under {kind}. The module must export
    `M.open(opts, picker_open)` and call `picker_open(picker_opts)` to render
    its picker. Subsequent `:lua require('fuzzy.picker').open_for({kind})`
    calls dispatch to it.

    Parameters: ~
        {kind}     (string) Identifier passed to |open_for|.
        {modname}  (string) Lua module name passed to `require()`.

    Built-in kinds: `files`, `buffers`, `grep`, `helptags`, `commands`,
    `keymaps`, `qflist`, `git_branches`, `git_worktrees`, `lsp_symbols`,
    `lsp_project_symbols`, `jumps`, `marks`, `registers`. They share the
    same contract, so the smallest example to copy is
    `lua/fuzzy/picker/sources/qflist.lua`.

    Example: >
        require('fuzzy.picker').register_source(
            'oldfiles', 'my_plugin.oldfiles_source'
        )
        vim.api.nvim_create_user_command('FuzzyOldfiles', function()
            require('fuzzy.picker').open_for('oldfiles')
        end, {})

6. EXAMPLES                                                  *fuzzy-examples*

Keybinding setup~
>
    local fuzzy = require('fuzzy')
    fuzzy.setup()

    -- Picker workflow (interactive)
    vim.keymap.set('n', '<leader>/', '<CMD>FuzzyGrep!<CR>', { desc = 'Live grep picker' })
    vim.keymap.set('n', '<leader>ff', '<CMD>FuzzyFiles!<CR>', { desc = 'File picker' })
    vim.keymap.set('n', '<leader>fb', '<CMD>FuzzyBuffers!<CR>', { desc = 'Buffer picker' })
    vim.keymap.set('n', '<leader>fh', '<CMD>FuzzyHelp<CR>', { desc = 'Help tag picker' })
    vim.keymap.set('n', '<leader>fc', '<CMD>FuzzyCommands<CR>', { desc = 'Command picker' })

    -- Quickfix workflow (type a pattern, results stream to QF)
    vim.keymap.set('n', '<leader>fg', ':FuzzyGrep ', { desc = 'Grep → QF' })

    -- Quickfix history
    vim.keymap.set('n', '<leader>fl', '<CMD>FuzzyList<CR>', { desc = 'History' })

    -- Grep word under cursor → QF
    vim.keymap.set('n', '<leader>fw', function()
        local word = vim.fn.expand('<cword>')
        if word ~= '' then fuzzy.grep({ word }) end
    end, { desc = 'Grep word' })

    -- Grep WORD (literal) → QF
    vim.keymap.set('n', '<leader>fW', function()
        local word = vim.fn.expand('<cWORD>')
        if word ~= '' then fuzzy.grep({ '-F', word }) end
    end, { desc = 'Grep WORD' })

    :FuzzyGrep TODO -t lua           " Lua files only → QF
